# Добавление почтового аккаунта

MailCopilot поддерживает любого почтового провайдера, использующего стандартные протоколы IMAP и SMTP. Также можно войти через Google или через аккаунт Microsoft 365 / Outlook.com с помощью OAuth — без ввода пароля.

## Мастер настройки

Нажмите **Подключить почту** (иконка письма внизу боковой панели) или откройте менеджер аккаунтов, чтобы увидеть мастер настройки.

### Шаг 1: Выберите вашего провайдера

Мастер начинается с явного выбора провайдера — вы сообщаете MailCopilot, какой почтой вы пользуетесь, ещё до ввода учётных данных. Каждый провайдер отображается в виде карточки с логотипом или иконкой провайдера:

- **Gmail** — сразу запускает OAuth-поток Google. Откроется окно браузера, в котором вы дадите MailCopilot доступ к вашему Gmail; пароль вводить не нужно.
- **Outlook / Microsoft 365** — запускает OAuth-поток Microsoft (Authorization Code с PKCE) и подключается через Microsoft Graph. Поддерживаются как личные аккаунты `@outlook.com` / `@hotmail.com` / `@live.com`, так и рабочие/учебные аккаунты Microsoft 365.
- **Generic IMAP/SMTP** — для любого другого провайдера (Yahoo, Fastmail, Яндекс, Mail.ru, ProtonMail Bridge, корпоративная почта, собственные серверы и так далее). Сначала открывает подтверждающий шаг с единственной кнопкой **IMAP/SMTP-аккаунт**, который ведёт к форме ввода учётных данных.

Между карточками можно перемещаться стрелками клавиатуры и подтверждать выбор клавишей **Enter** или **Пробел**. После выбора провайдера мастер продолжает шаги, соответствующие именно ему. На пути Generic IMAP/SMTP кнопка **Назад** на подтверждающем шаге возвращает к provider picker; на шаге ввода учётных данных также есть кнопка **Назад**, и она возвращает на подтверждающий шаг (по одному шагу за раз). Шаги определения сервера и ручной настройки идут только вперёд — чтобы начать заново с другим провайдером, отмените мастер и откройте его снова.

Если для Outlook вы хотите подключиться через Generic IMAP/SMTP вместо OAuth, выберите карточку Generic и используйте app password против `outlook.office365.com` / `smtp.office365.com`.

### Шаг 2: Введите учётные данные (Generic IMAP/SMTP)

Если вы выбрали Generic IMAP/SMTP:

1. Введите **адрес электронной почты** и **пароль**.
2. При желании укажите **отображаемое имя** (имя в исходящих письмах).
3. Опционально введите **email-адрес (От кого)** -- этот адрес используется в поле «От» исходящих сообщений. Если не указан, используется адрес SMTP-логина.
4. Если учётные данные SMTP отличаются от IMAP, отметьте **«Логин/пароль SMTP отличается»** и введите их отдельно.
5. Нажмите **Далее**.

### Шаг 3: Определение сервера

MailCopilot попытается автоматически определить настройки почтового сервера с помощью стандартных протоколов автообнаружения. В случае успеха обнаруженные серверы IMAP и SMTP отображаются в редактируемых полях. Вы можете просмотреть и изменить отображаемое имя, адрес электронной почты, хосты серверов, порты и настройки SSL перед подключением.

- Нажмите **Подключить**, чтобы проверить соединение и сохранить аккаунт.
- Если вам нужен полный ручной контроль над всеми настройками (включая отдельные учётные данные IMAP/SMTP), нажмите **Ручная настройка**.

### Ручная настройка

Если автоматическое определение не нашло ваш сервер:

- **IMAP**: укажите хост, порт (обычно 993) и отметьте SSL/TLS.
- **SMTP**: укажите хост, порт (обычно 465 или 587) и отметьте SSL/TLS.
- Кнопка **Автонастройка** позволяет повторить автоматическое определение.
- Кнопка **Проверить соединение** проверяет настройки перед сохранением.

## Аккаунт Google (OAuth)

Выберите карточку **Gmail** в мастере. Откроется окно браузера, где вы авторизуете MailCopilot. После авторизации аккаунт добавляется автоматически с правильными настройками IMAP и SMTP.

Пока идёт подключение, мастер вместо списка провайдеров показывает шаг с текущей стадией: подтверждение доступа в браузере, получение доступа, проверка почтового сервера и сервера отправки, сохранение аккаунта. Предельное время задано у двух частей: ожидание вашего подтверждения в браузере (три минуты) и проверки серверов (30 секунд для входящей почты и 15 для исходящей, с одной повторной попыткой). У остального его нет; остальное зависит от провайдера и вашей сети, поэтому шаг показывает, что происходит сейчас, а не сколько осталось. Если у аккаунта ещё нет имени и провайдер сообщил пригодное, оно подставляется из профиля; имя, которое вы задали сами, при повторной авторизации не перезаписывается. Если подключение не удалось до сохранения аккаунта, мастер возвращается к списку провайдеров, чтобы можно было попробовать снова. Закрытие окна не отменяет уже начатое подключение — оно продолжится в фоне и может всё-таки добавить аккаунт, поэтому повторная попытка в этот момент рискует оставить дубликат. Этот шаг относится к добавлению аккаунта: при повторной авторизации существующего в его настройках показывается только индикатор на кнопке.

## Аккаунт Microsoft 365 / Outlook (OAuth)

Выберите карточку **Outlook / Microsoft 365** в мастере. Откроется окно браузера со страницей входа Microsoft; войдите с помощью аккаунта `@outlook.com`, `@hotmail.com`, `@live.com` или рабочего/учебного аккаунта и подтвердите запрашиваемые разрешения. Стандартный (bundled) Microsoft-клиент использует Authorization Code с PKCE без client secret — никакой client secret не покидает ваше устройство. Кастомные сборки, переопределяющие bundled-клиент через **обе** env var `MAILCOPILOT_MS_CLIENT_ID` (своя регистрация Azure-приложения) и `MAILCOPILOT_MS_CLIENT_SECRET` (для тенантов с confidential client), действительно отправляют этот секрет в endpoint токена Microsoft по TLS. `MAILCOPILOT_MS_CLIENT_SECRET` сам по себе (без своего client ID) игнорируется. После авторизации аккаунт добавляется автоматически.

Здесь появляется тот же экран ожидания, что и для Gmail, — с теми же стадиями и теми же оговорками: предельное время есть у ожидания в браузере и у проверок серверов, у остального нет, закрытие окна начатое подключение не отменяет. Повторной попытки для сервера отправки, в отличие от Gmail, здесь нет. Имя берётся из профиля Microsoft, если у аккаунта его нет и профиль сообщил пригодное; заданное вами имя при повторной авторизации не перезаписывается. Запрос на доверие сертификату, описанный ниже для Google, возникает и на этом пути — уже после сохранения аккаунта.

Для отправки писем на Outlook-аккаунтах MailCopilot использует Microsoft Graph (`POST /me/sendMail`), потому что Microsoft отключила SMTP AUTH на большинстве личных Outlook.com-аккаунтов, созданных с 2024 года. На Graph send path это ограничение не распространяется. Отправленные сообщения автоматически сохраняются Microsoft в папку «Отправленные».

Если ваш Outlook-аккаунт перестал работать после долгого офлайна, OAuth refresh token мог истечь. Если OAuth refresh token отсутствует в защищённом хранилище, [уведомление об истёкшем входе](#уведомление-об-истёкшем-входе) появляется сразу — это верно и для Google, и для Outlook. Если сохранённый токен отвергнут провайдером, возникший в результате отказ IMAP-авторизации идёт по обычному сценарию неудачного входа; переавторизуйте аккаунт в **Настройки > Аккаунты** с помощью кнопки повторной аутентификации Microsoft.


## Проверка TLS-сертификата

MailCopilot всегда проверяет TLS-сертификаты при подключении к почтовым серверам, сверяя их со встроенным набором сертификатов Mozilla и с хранилищем сертификатов вашей операционной системы (переходя на один встроенный набор Mozilla, если хранилище ОС прочитать не удаётся). Если ваш сервер использует пользовательский или самоподписанный сертификат, при проверке соединения появится запрос на доверие. Вы можете просмотреть детали сертификата и решить, доверять ему или нет: если отпечаток ещё не получен, кнопка сначала называется **«Получить сертификат»** — нажмите её, просмотрите детали, затем подтвердите кнопкой **«Доверять и продолжить»**; если кнопка **«Доверять и продолжить»** показана сразу, нажмите только её. Серверы, к которым подключение идёт через STARTTLS (обычно IMAP-порт 143 или SMTP-порт 587), не могут передать свой сертификат на этом шаге, поэтому для них сохраняется только отпечаток — самоподписанный сервер на STARTTLS так нельзя сделать доверенным; если ваш сервер это поддерживает, используйте вместо этого прямое TLS-соединение (обычно порт 993 или 465).

При входе через Google, если ваша сеть использует прокси или антивирус, подменяющий TLS-сертификаты на такие, которым ваша операционная система ещё не доверяет, MailCopilot обнаружит это и автоматически предложит принять сертификат. Вы увидите детали сертификата (хост, издатель, отпечаток) и сможете принять или отклонить его. Аккаунт сохраняется в любом случае, а управление сертификатами доступно позже в настройках аккаунта. Если же корневой сертификат прокси или антивируса уже установлен в хранилище вашей ОС, соединение пройдёт без какого-либо запроса на доверие — MailCopilot отметит этот случай отдельно информационным уведомлением (см. ниже), а не попросит что-то подтверждать.

Доверие системному хранилищу сертификатов означает, что большинство корпоративных прокси и антивирусов, проверяющих TLS-трафик, работают из коробки, без запроса на доверие во время настройки. После первой успешной синхронизации аккаунта в сессии MailCopilot один раз проверяет, не проверяется ли соединение таким образом, и если да — показывает уведомление с названием программы или прокси, ответственных за это; эта проверка выполняется не более одного раза на сервер за всё время профиля, поэтому перехват, включённый на сервере позже, после того как эта проверка уже прошла, замечен не будет. Если сертификат сервера позже изменится на такой, которому вообще нельзя доверять, MailCopilot покажет диалог восстановления прямо в основном окне — подробнее см. [Доверие TLS-сертификатам](../settings/general#доверие-tls-сертификатам).

## Несколько аккаунтов

Вы можете добавить сколько угодно аккаунтов. Для переключения между ними используйте боковую панель или перейдите в **Настройки > Аккаунты**. Активный аккаунт выделен, и вы можете назначить любой аккаунт текущим.

## Уведомление об истёкшем входе

Если учётные данные аккаунта перестают работать — например, IMAP-пароль был изменён в другом месте, или для аккаунта вообще не сохранён ни пароль, ни OAuth-авторизация, — MailCopilot больше не отказывает молча в фоне. Над списком писем появляется тихое уведомление: например, «Ящик «Почтовый аккаунт» не получает почту — вход устарел. Войдите снова, чтобы синхронизация продолжилась». При обычном сбое входа в ходе повседневной работы с почтой уведомление появляется только после двух подряд неудачных попыток для одного и того же аккаунта. Есть два случая, которые пропускают этот порог и показывают уведомление сразу. Первый — аккаунт вовсе без сохранённых учётных данных: повторять попытку тут нечего. Второй — вход, который почтовый сервер отверг в момент, когда MailCopilot запускает фоновое отслеживание почты (IMAP IDLE) для этого аккаунта: полноценная попытка входа, которую сервер отклонил, — это окончательный вердикт о сохранённых учётных данных, а не просто одна операция, которая не сработала, поэтому ждать второй неудачи бессмысленно — а у ящика, где все папки настроены на ручное обновление, второй фоновой синхронизации для повторной неудачи может и не быть. Нажмите **Войти снова**, чтобы сразу перейти в настройки этого аккаунта, где можно заново ввести пароль или повторно авторизовать OAuth-подключение.

Уведомление появляется только из-за проблем со входом (аутентификацией), о которых сообщил сам почтовый сервер, — временный сбой сети или проблема с сертификатом его не вызывают, поскольку у каждого из этих случаев уже есть собственный отдельный индикатор (см. [Проверка TLS-сертификата](#проверка-tls-сертификата) выше). OAuth refresh token, отсутствующий в защищённом хранилище, вызывает уведомление сразу — и для Google, и для Outlook. Если сохранённый токен отвергнут, возникший в результате отказ IMAP-авторизации идёт по обычному сценарию неудачного входа; в этом случае переавторизуйте аккаунт вручную в **Настройки > Аккаунты**. Оно исчезает автоматически, как только для этого аккаунта успешно проходит любое обращение к серверу — не только фоновая синхронизация, но и открытие письма, перемещение почты или поиск, — поэтому даже аккаунт, у которого все папки настроены на ручное обновление, снимает уведомление сразу же, как только вы им воспользуетесь. Закрывать уведомление вручную не нужно. Это состояние не сохраняется между перезапусками — если MailCopilot закрыт, пока аккаунт отмечен, уведомление появится снова только после того, как та же последовательность неудач повторится после следующего запуска.

## Настройка аватара аккаунта

Каждый аккаунт отображается в боковой панели с аватаром -- цветной кружок с инициалами. Вы можете настроить аватар в **Настройки > Аккаунты**, нажав на иконку палитры рядом с аккаунтом.

### Режимы отображения

- **Буквы** -- цветной кружок с 1--2 символами (инициалами). Вы можете ввести собственные инициалы, если автоматические не подходят (например, когда у всех аккаунтов одно и то же имя).
- **Иконка** -- цветной кружок с иконкой из набора (почта, портфель, звезда, ракета и др.).
- **Gravatar** -- загружает фото профиля из [Gravatar](https://gravatar.com) по вашему email-адресу. Если Gravatar не найден, отображаются буквы.

### Изменение цвета

Нажмите на любой цвет в палитре, чтобы изменить фон аватара. Цвет сохраняется и не меняется при перезапуске.

### Всплывающая подсказка

При наведении на аватар аккаунта в боковой панели появляется подсказка с именем и email-адресом.

## Поддерживаемые провайдеры

MailCopilot работает с любым провайдером, поддерживающим IMAP/SMTP:

- Gmail (через OAuth или пароль приложения)
- Outlook / Microsoft 365
- Yahoo Mail
- Fastmail
- Яндекс Почта
- Mail.ru
- ProtonMail (через ProtonMail Bridge)
- Собственные серверы (Dovecot, Postfix, Zimbra и др.)

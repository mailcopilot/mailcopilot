# Основные настройки

Откройте окно настроек, нажав на иконку шестерёнки в боковой панели.

## Тема

Выберите **Светлую** или **Тёмную** тему. Интерфейс обновляется мгновенно при переключении. В тёмном режиме окна открываются с тёмным фоном с самого первого кадра — без белой вспышки.

## Язык

MailCopilot поддерживает 6 языков интерфейса:

- English
- Русский
- Français
- Deutsch
- Español
- Italiano

Выберите язык в выпадающем списке. Интерфейс переключается мгновенно без перезапуска.

## Срок хранения писем

Управляет тем, как долго полные копии писем (HTML-содержимое, встроенные изображения и вложения) хранятся на диске. Откройте **Настройки > Общие** и выберите период в выпадающем списке **Хранить полные тела писем**. Более старые письма по-прежнему доступны для поиска через заголовки и текст — удаляется только файл `.eml` с расширенным содержимым.

| Вариант | Срок |
|---------|------|
| 30 дней | ~1 месяц |
| 90 дней | ~3 месяца |
| 180 дней | ~6 месяцев |
| 1 год | 365 дней (по умолчанию) |
| Бессрочно | Без автоматической очистки |

При уменьшении срока хранения MailCopilot показывает предварительный просмотр того, сколько писем будет удалено из кэша перед применением изменений. Письма на сервере не изменяются — затрагивается только локальная копия.

## Почтовый клиент по умолчанию

Переключатель определяет, регистрируется ли MailCopilot в операционной системе как обработчик ссылок `mailto:`. Если включено, нажатие на ссылку «отправить email» в браузере, терминале или другом приложении откроет окно написания письма MailCopilot с уже заполненными получателем и прочими параметрами (`to`, `cc`, `bcc`, `subject`, `body`).

Регистрация происходит только по вашему явному согласию — MailCopilot не претендует на протокол, пока вы не включите переключатель. На Linux регистрация идёт через объявление `MimeType` в desktop-файле; на macOS — через `open-url`; на Windows — через запись о протоколе в `HKCR\mailto`. Откатиться можно в любой момент: либо выключив этот переключатель, либо изменив почтовый клиент по умолчанию в системных настройках.

Если MailCopilot запускается во второй раз — например, по нажатию на ссылку `mailto:` при уже открытом приложении — существующее окно выводится поверх и получает фокус вместо открытия дубликата, поэтому в каждый момент работает ровно один экземпляр.

## Проверка орфографии

Проверка орфографии по умолчанию **выключена**. Включение загружает файл словаря со стороннего сервера (сервера Google), и MailCopilot сначала спрашивает разрешение — при добавлении каждого нового языка. Это сделано намеренно: MailCopilot никогда не включает язык, который вы не одобрили. Саму загрузку выполняет браузерный движок, встроенный в приложение (Chromium), обращаясь к серверу Google — MailCopilot не может отменить уже начавшийся запрос. Если загрузка всё же начнётся для неодобренного языка, MailCopilot замечает это и снова выключает проверку орфографии, вместо того чтобы оставить её незаметно включённой.

Включите **«Проверять орфографию при наборе»**, чтобы включить проверку. После этого слова с ошибками подчёркиваются везде, где можно печатать текст — в письмах, полях настроек и так далее.

### Выбор словарей

После включения проверки орфографии используйте раздел **«Словари»**, чтобы добавить один или несколько языков. Список доступных языков берётся из самого движка проверки орфографии, а не из фиксированного списка, зашитого в MailCopilot, — то, что вы видите, зависит от того, что реально может предложить именно эта сборка приложения. Можно добавить сразу несколько языков — все они проверяются одновременно. Каждый добавленный язык можно снова убрать кнопкой **«Удалить»**. Если «Проверять орфографию при наборе» включено, но ни один словарь не выбран, проверка орфографии фактически остаётся выключенной — словарь обязателен.

Число одновременно активных словарей ограничено; текущий предел показан рядом с выбором языка.

### Разрешение на загрузку

При первом добавлении языка, который раньше не был разрешён, MailCopilot показывает диалог с вопросом, загружать ли словарь для этого языка, и называет сторонний сервер, с которого придёт файл. То, что вы печатаете, никогда никуда не отправляется — проверка всегда происходит на вашем компьютере; загружается только сам файл словаря.

- Нажатие **«Загрузить»** разрешает язык: MailCopilot запоминает это разрешение и позволяет загрузке пройти. Разрешение сохраняется для этого языка на будущее — если словарь понадобится загрузить снова позже (например, после повторного включения языка, который вы уже одобрили), это произойдёт без повторного вопроса.
- Нажатие **«Отмена»** (или закрытие диалога) означает отказ: этот язык **не** включается, но отказ не запоминается как окончательный — вы можете добавить тот же язык позже, и вас просто снова спросят. Остальные изменения, сделанные в то же сохранение, всё равно применяются: отказ от загрузки словаря никогда не блокирует остальные ваши изменения.

### macOS

На macOS проверкой орфографии владеет операционная система, а не MailCopilot. На macOS нет ни выбора словарей, ни диалога с разрешением на загрузку, потому что macOS ничего не загружает и игнорирует любой список языков, который MailCopilot мог бы ей передать, — в настройках это объясняется, и показывается только переключатель «вкл/выкл». Чтобы изменить языки, которые проверяет macOS, откройте «Системные настройки» → «Клавиатура» → «Ввод текста».

### Исправление слова с ошибкой

Щёлкните правой кнопкой мыши по слову, подчёркнутому как ошибочное, чтобы увидеть короткий список предложенных замен, а также пункт **«Добавить в словарь»**. Клик по варианту заменяет слово; **«Добавить в словарь»** добавляет слово в ваш личный словарь, чтобы оно больше не подчёркивалось. Сейчас в MailCopilot нет способа посмотреть или удалить слова, добавленные в личный словарь.

## Значок в системном трее и работа в фоне

MailCopilot умеет показывать значок в системном трее. Опция **«Показывать значок в трее»** включена по умолчанию; её меню предлагает пункты **«Открыть MailCopilot»**, **«Новое письмо»**, **«Проверить почту»** и **«Выход»**, а пока значок существует, наведение на него показывает число непрочитанных писем во всплывающей подсказке — до 999, дальше показывается **«999+»**.

### Закрывать окно в трей

Включите **«Закрывать окно в трей»** (по умолчанию выключено), чтобы при закрытии главного окна MailCopilot продолжал работать вместо выхода — почта продолжает синхронизироваться в фоне, и уведомления о новых письмах продолжают приходить. Чтобы вернуть окно, нажмите на значок в трее (или пункт **«Открыть MailCopilot»** в его меню); чтобы действительно выйти из приложения, используйте пункт **«Выход»** в меню трея.

Выбор пункта **«Выход»** не убирает значок в трее сразу. Прежде чем действительно завершить работу, MailCopilot делает контрольную точку локальной базы данных — из-за этого возникает небольшая задержка, обычно заметно меньше секунды. Пока это происходит, всплывающая подсказка значка в трее показывает **«Завершение работы…»**, а его меню вместо обычных пунктов показывает единственную неактивную строку **«Завершение работы…»** — чтобы было видно, что приложение ещё завершает работу, а не что «Выход» просто убрал значок. Если в момент выхода письмо ещё отправлялось, оно не теряется: MailCopilot отправляет почту через локальную очередь, поэтому незавершённая отправка просто остаётся в очереди и уходит при следующем запуске MailCopilot.

Эта настройка зависит от того, удалось ли создать значок в трее, а не от того, рисует ли его кто-то: на Linux MailCopilot создаёт значок даже тогда, когда его не принимает ни один хост трея, поэтому **«Закрывать окно в трей»** работает всегда, когда объект значка существует — независимо от того, показывает ли его на самом деле рабочий стол. Опция не действует только если MailCopilot вообще не смог создать значок (пустое или нечитаемое изображение значка, либо платформа, отказавшаяся его создавать).

Перед тем как спрятать окно, MailCopilot не проверяет, отрисовывает ли рабочий стол значок на самом деле — это решение рабочего стола, а не MailCopilot; подсказка под настройкой отмечает это для Linux. Если значок так и не отрисован, нажимать будет не на что, но сокрытие в любом случае обратимо: повторный запуск MailCopilot возвращает спрятанное окно на передний план, независимо от того, работает значок, отрисован неверно или не появился вовсе.

Если уведомления включены, при первом за сеанс сокрытии окна в трей MailCopilot показывает короткое одноразовое уведомление о том, что приложение продолжает работать в фоне и что окно можно вернуть щелчком по значку в трее.

Если вы когда-нибудь закрыли MailCopilot, ожидая, что он останется в трее, а найти его не можете, см. [Я закрыл окно, и теперь не могу найти MailCopilot](../faq#я-закрыл-окно-и-теперь-не-могу-найти-mailcopilot) в разделе часто задаваемых вопросов.

### Значок непрочитанных писем

Пока есть непрочитанные письма, MailCopilot показывает значок на иконке приложения — числовой бейдж в доке (macOS) или лаунчере Unity (Linux) и точку на кнопке панели задач (Windows); само число (до 999, дальше — **«999+»**) доступно во всплывающей подсказке значка в трее, пока этот значок существует. Значок учитывает те же папки, которые вы исключили из подсчёта непрочитанных в [настройках папок](folders-settings#бейджи-непрочитанных).

### Запуск при входе в систему

Включите **«Запускать при входе в систему»** (по умолчанию выключено), чтобы MailCopilot запускался автоматически при входе в вашу учётную запись. На Windows и macOS это регистрирует MailCopilot как элемент автозагрузки в операционной системе; на Linux создаётся запись автозапуска (файл `.desktop`), чтобы окружение рабочего стола запускало MailCopilot при входе.

Переключатель фиксирует то, что вы запросили; подсказка под ним появляется всякий раз, когда фактический результат не совпадает с запросом. Если эта платформа или сборка вообще не может зарегистрировать автозапуск, MailCopilot сообщает, что настройка здесь ни на что не влияет. Если включение не удалось, подсказка поясняет, что автозапуск не удалось зарегистрировать и попытка повторится при следующем сохранении. Если не удалось выключение, MailCopilot сообщает, что приложение всё равно будет запускаться при входе в систему и что удаление будет повторено автоматически при следующем сохранении — так вы никогда не окажетесь в ситуации, когда думаете, что автозапуск выключен, а на самом деле он всё ещё работает.

## Доверие TLS-сертификатам

MailCopilot проверяет каждый TLS-сертификат, предъявленный вашими почтовыми серверами, по встроенному набору сертификатов Mozilla и по хранилищу сертификатов вашей операционной системы. Доверие системному хранилищу означает, что программы, перехватывающие TLS-трафик (например, Kaspersky и подобные антивирусы), а также корпоративные прокси больше не мешают синхронизации почты на Windows, macOS и Linux — MailCopilot распознаёт сертификаты, предъявляемые такими программами, как действительные, вместо того чтобы отклонять соединение. Проверка сертификатов при этом не ослабляется: сертификату по-прежнему нужно быть доверенным одним из этих двух источников или явно закреплённым, чтобы быть принятым. Если хранилище сертификатов операционной системы прочитать не удаётся, MailCopilot переходит на встроенный набор Mozilla в одиночку, а не пропускает проверку.

### Восстановление после смены сертификата

Если сервер когда-либо предъявит сертификат, которому нельзя доверять — например, он больше не совпадает с ранее принятым сертификатом, или самоподписанный сертификат изменился после ротации — MailCopilot покажет диалог **«Сервер предъявил другой сертификат»** прямо в основном окне, а не только во время настройки аккаунта. В диалоге указаны сервер, издатель и отпечаток SHA-256 нового сертификата.

Подтверждение происходит в два шага, чтобы то, что вы одобряете, всегда совпадало с тем, что показано на экране:

- Если отпечаток ещё не получен, основная кнопка называется **«Получить сертификат»**. Нажмите её, чтобы получить сертификат с сервера — его данные заменят собой заглушку в диалоге.
- Когда отпечаток уже показан, кнопка называется **«Доверять и продолжить»**. Нажмите её, чтобы принять именно тот сертификат, который отображён на экране.
- Если сертификат сервера снова изменится между открытием диалога и подтверждением, MailCopilot откажется от устаревшего подтверждения и заново прочитает сертификат, чтобы показать новые данные — но предложение доверия было привязано к сертификату, показанному изначально, и повторное чтение его не обновляет, поэтому повторное подтверждение будет так же отклоняться. Нажмите **«Отмена»**, чтобы закрыть этот диалог, и дайте MailCopilot попробовать подключиться снова — появится новый диалог с актуальным сертификатом, который и нужно подтвердить. Пока это не произойдёт, ничего не будет доверено.

В любой момент можно нажать **«Отмена»**, чтобы оставить прежнее состояние. Повторно этот диалог для того же сервера не появится чаще раза в минуту. Предложение довериться сертификату тоже не остаётся открытым бесконечно — если диалог провисел без ответа долго, подтверждение может быть отклонено; и в этом случае отмените и дождитесь нового диалога.

### Повторное подтверждение закреплённого самоподписанного сервера после обновления

Закрепление сертификатов теперь строго применяется для сертификатов, не проходящих обычную проверку цепочки: раньше закрепление сравнивало отпечатки только для сертификатов с уже нормально проверенной цепочкой, а самоподписанные сертификаты и сертификаты приватных центров сертификации — тот самый случай, ради которого закрепление существует — вообще обходили проверку отпечатка. Теперь этот пробел закрыт. Если вы закрепили самоподписанный сервер или сервер с приватным центром сертификации до этого изменения, сохранённое закрепление могло содержать только отпечаток без самого сертификата, необходимого для реальной проверки — такой сервер перестанет подключаться после обновления, и MailCopilot покажет описанный выше диалог восстановления сертификата.

Чтобы это исправить, подтвердите сертификат заново именно через этот диалог: если кнопка называется **«Получить сертификат»**, сначала нажмите её, чтобы получить сертификат, а затем нажмите **«Доверять и продолжить»**; если сразу показана кнопка **«Доверять и продолжить»**, нажмите только её. Это сохранит закрепление вместе с самим сертификатом, и синхронизация возобновится автоматически. Это нужно сделать только один раз для каждого затронутого сервера. Добавление или редактирование закрепления вручную в **Настройках** само по себе эту проблему не решает — для сертификата, который иначе остаётся недоверенным (самоподписанного или от приватного центра сертификации, ещё не добавленного в хранилище вашей ОС), доверие может выдать только диалог восстановления; см. [Когда использовать закрепление сертификатов](#когда-использовать-закрепление-сертификатов) ниже, почему это так.

### Уведомление о перехвате

После первой успешной синхронизации аккаунта в сессии MailCopilot один раз проверяет, не проверяется ли соединение с почтовым сервером антивирусом или прокси (сертификат доверенный только через системное хранилище), и если да — показывает уведомление вида «Соединение с `{{host}}` проверяется.», указывая издателя, если он известен. Эта проверка выполняется не более одного раза на сервер за всё время существования профиля — независимо от того, был ли обнаружен перехват. Поэтому если перехват на сервере включат позже, уже после того как эта разовая проверка прошла, MailCopilot этого не заметит. Уведомление можно закрыть.

Ошибки сертификата повторяются с длинным интервалом (6 часов), а не с коротким интервалом для обычных сетевых сбоев, поскольку они требуют вашего решения и не разрешатся сами по себе.

## Закрепление TLS-сертификатов

Закрепление TLS-сертификатов добавляет дополнительный уровень безопасности для ваших почтовых подключений. Оно гарантирует, что клиент подключается только к серверам с определённым сертификатом, защищая от атак типа «человек посередине».

### Управление закреплёнными сертификатами

1. Откройте **Настройки** и перейдите в раздел **Аккаунты**.
2. Нажмите **Редактировать** на аккаунте, чтобы открыть его настройки.
3. Прокрутите вниз до раздела **Закрепление TLS-сертификатов**.

В разделе отображается таблица закреплённых сертификатов с указанием хоста, порта, отпечатка и даты добавления.

### Добавление закрепления

1. Нажмите **Добавить pin**.
2. Введите **хост** (например, `imap.gmail.com`) и **порт** (например, `993`).
3. Нажмите **Загрузить и закрепить**. MailCopilot подключится к серверу, получит его сертификат и покажет вам отпечаток.
4. Подтвердите сохранение закрепления.

Закрепление, добавленное таким способом, только *сужает* круг принимаемых сертификатов для сервера, который уже доверенный через обычный набор Mozilla или хранилище вашей ОС — само по себе оно не делает доверенным самоподписанный сертификат или сертификат приватного центра сертификации, который иначе остаётся недоверенным. Для самоподписанного почтового сервера (или сервера с приватным центром сертификации, ещё не добавленным в хранилище вашей ОС) добавления закрепления здесь недостаточно для подключения — его нужно подтвердить через диалог восстановления сертификата, описанный в разделе [Доверие TLS-сертификатам](#доверие-tls-сертификатам): только там MailCopilot выдаёт доверие такому сертификату.

### Удаление закрепления

Нажмите кнопку удаления рядом с любым закреплением в таблице. Это только удаляет сохранённое закрепление — после этого MailCopilot будет принимать любой действительный сертификат от этого сервера.

Добавление закрепления автоматически переподключает MailCopilot к почтовому серверу, чтобы изменение вступило в силу немедленно. Удаление закрепления автоматического переподключения не вызывает — оно вступит в силу при следующем подключении MailCopilot к этому серверу.

### Серверы со STARTTLS (порты 143 и 587)

Серверы, к которым подключение идёт через STARTTLS (обычно IMAP-порт 143 или SMTP-порт 587, где соединение начинается в открытом виде и затем переходит на TLS), не передают свой сертификат в тот момент, когда MailCopilot захватывает его для закрепления. Для таких серверов сохраняется только отпечаток, а не сам сертификат — поэтому самоподписанный сервер или сервер с приватным центром сертификации на STARTTLS не получится подключить этим способом; если ваш сервер это поддерживает, используйте прямое TLS-соединение (обычно порт 993 для IMAP, 465 для SMTP).

### Когда использовать закрепление сертификатов

Закрепление сертификатов особенно полезно в корпоративной среде или в ситуациях, когда необходимо убедиться, что почтовые подключения идут к ожидаемым серверам. Для большинства личных пользователей стандартной TLS-верификации достаточно.
